# Yandex SmartCaptcha для анкеты Samotsvet

Дата проверки инструкции: 4 сентября 2026 года.

## Что меняется

Сайт остается статическим на GitHub Pages, но отправлять анкету напрямую в публичный `LeadCapture` EspoCRM после включения CAPTCHA нельзя. Ключ проверки должен находиться только на российском сервере.

Целевая схема:

1. посетитель заполняет подробную анкету оценки шансов;
2. браузер получает одноразовый токен невидимой Yandex SmartCaptcha;
3. сайт отправляет токен и анкету на новый endpoint российского сервера;
4. сервер проверяет Origin, honeypot и лимит `3 отправки / IP / 60 минут`;
5. сервер валидирует токен в Yandex SmartCaptcha;
6. только после успешной проверки сервер создает Lead в локальной EspoCRM;
7. при отказе проверки пользователь видит повторную попытку и кнопку Telegram.

## Почему нельзя добавить только виджет на сайт

Клиентский ключ можно публиковать. Серверный ключ нельзя помещать в GitHub, JavaScript, `NEXT_PUBLIC_*` или HTML. Без серверного запроса на `/validate` злоумышленник просто пропустит виджет и вызовет CRM endpoint напрямую.

## Шаг 1. Создать CAPTCHA

1. Войти в [консоль Yandex Cloud](https://console.yandex.cloud/).
2. Подключить платежный аккаунт в статусе `ACTIVE` или `TRIAL_ACTIVE`. Он требуется даже при небольшом объеме запросов.
3. Открыть `Yandex SmartCaptcha → Создать капчу`.
4. Назвать ресурс `samotsvet-options-assessment`.
5. В список сайтов добавить:
   - `samotsvetvisa.com`;
   - `www.samotsvetvisa.com`, только если этот адрес реально используется;
   - отдельный тестовый домен, если он будет применяться.
6. Выбрать среднюю сложность. Невидимость задается в коде виджета, а не заменяет настройку доменов.
7. Отключить использование HTTP-запросов для развития ML-моделей, если это соответствует принятой политике обработки данных.
8. Создать ресурс и скопировать два значения:
   - ключ клиента – для сайта;
   - ключ сервера – только для российского backend.

## Шаг 2. Сохранить ключи

На сервере создать переменные окружения:

```text
SMARTCAPTCHA_CLIENT_KEY=<клиентский ключ>
SMARTCAPTCHA_SERVER_KEY=<серверный ключ>
LEAD_CAPTURE_INTERNAL_URL=<внутренний URL действующего LeadCapture>
LEAD_RATE_LIMIT_SECRET=<отдельная случайная строка для хеширования IP>
```

`SMARTCAPTCHA_SERVER_KEY` и текущий идентификатор LeadCapture нельзя записывать в публичный репозиторий или отдавать браузеру после перехода на прокси.

## Шаг 3. Сделать серверный endpoint

Рекомендуемый адрес: `POST https://crm.samotsvetvisa.com/forms/options-assessment`.

Endpoint принимает JSON:

```json
{
  "smartToken": "одноразовый токен",
  "website": "",
  "lead": {
    "firstName": "Имя",
    "cContact": "контакт",
    "cCountry": "Compare",
    "cObjective": "цель переезда",
    "cTiming": "6-12 months",
    "cCitizenship": "гражданство",
    "cResidence": "страна проживания и статус",
    "cFamily": "Alone",
    "cEmployment": "Employee",
    "cProfile": "профессиональный или предпринимательский профиль",
    "cEvidence": "имеющиеся подтверждения",
    "cStage": "Exploring routes",
    "cConsent": true,
    "cFormSource": "chance-assessment-ru"
  }
}
```

Порядок проверок на сервере:

1. разрешить только `POST` и `OPTIONS`;
2. разрешить Origin только `https://samotsvetvisa.com`;
3. отклонить тело больше 100 КБ;
4. если `website` заполнено, вернуть нейтральный `202`, но Lead не создавать;
5. вычислить `HMAC-SHA256(IP, LEAD_RATE_LIMIT_SECRET)` и посчитать успешные попытки за последние 60 минут;
6. при четвертой попытке вернуть `429` и `Retry-After`;
7. отправить токен на SmartCaptcha;
8. принять ответ только при `status: ok` и ожидаемом `host`;
9. удалить `smartToken`, `website` и технические поля;
10. передать в EspoCRM только разрешенный список полей действующей анкеты;
11. создать Lead через внутренний вызов EspoCRM;
12. вернуть браузеру только `200`, `400`, `429` или `503`, не раскрывая ответ CRM и ключи.

IP в таблице лимитов хранить только в виде HMAC-хеша. Записи старше 24 часов удалять автоматически.

## Шаг 4. Проверить токен на сервере

SmartCaptcha принимает `application/x-www-form-urlencoded`:

```bash
curl -X POST https://smartcaptcha.cloud.yandex.ru/validate \
  -d "secret=<ключ сервера>" \
  -d "token=<токен из формы>" \
  -d "ip=<IP пользователя>"
```

Успех:

```json
{"status":"ok","message":"","host":"samotsvetvisa.com"}
```

Токен одноразовый и, согласно документации Yandex, действует пять минут. Повторно использовать его нельзя. Поле `message` предназначено для диагностики, а бизнес-логика должна опираться на `status`.

Для формы с дорогим лидом разумен контролируемый `fail-open`: если Yandex вернул сетевую ошибку или HTTP не `200`, пропустить заявку только после успешных проверок Origin, honeypot и rate limit, записать техническое событие без содержимого анкеты и уведомить администратора. Ответ `status: failed` всегда блокирует отправку.

## Шаг 5. Подключить невидимый виджет

Скрипт:

```html
<script
  src="https://smartcaptcha.cloud.yandex.ru/captcha.js?render=onload&onload=onSmartCaptchaLoad"
  defer
></script>
```

Параметры отрисовки:

```js
const widgetId = window.smartCaptcha.render("captcha-container", {
  sitekey: "<ключ клиента>",
  invisible: true,
  callback(token) {
    sendLeadToRussianProxy(token);
  },
});

window.smartCaptcha.execute(widgetId);
```

Проверку запускать после нажатия `Отправить на оценку`, а не при первом открытии анкеты. Кнопку временно блокировать, пока идет проверка и отправка.

Не скрывать стандартный информационный shield SmartCaptcha. Если его все же скрывают параметром `hideShield`, рядом с кнопкой отправки нужно явно сообщить об обработке данных SmartCaptcha и обновить политику конфиденциальности.

## Шаг 6. Сообщения пользователю

При `status: failed`:

> Не удалось подтвердить, что Вы человек. Попробуйте еще раз или напишите нам в Telegram – @samotsvetvisa.

При `429`:

> За последний час с этого подключения уже отправлено несколько анкет. Попробуйте позже или напишите нам в Telegram.

При `503`:

> Анкета временно не отправляется. Ваши ответы остаются на этой странице. Попробуйте еще раз или напишите нам в Telegram.

В блоке ошибки формы уже подготовлена кнопка прямого сообщения в Telegram. Ссылка на канал остается отдельной в футере.

## Шаг 7. Переключить сайт без потери лидов

1. Развернуть новый endpoint, не меняя действующий сайт.
2. Проверить неверный Origin, заполненный honeypot, пустой и просроченный токен.
3. Отправить один явно помеченный тестовый Lead через новый endpoint.
4. Убедиться, что создана ровно одна карточка и все поля сохранились.
5. Проверить четыре отправки с одного тестового IP: первые три проходят, четвертая получает `429`.
6. Только после этого заменить endpoint в `AssessmentForm.tsx` на `/forms/options-assessment` и добавить получение токена.
7. Опубликовать сайт и повторить один контрольный тест.
8. Удалить тестовый Lead отдельным подтвержденным действием.

## Что нельзя делать

- хранить серверный ключ в статическом сайте;
- валидировать токен только в браузере;
- оставлять публичный LeadCapture доступным в обход нового endpoint;
- отправлять анкету в Yandex вместе с токеном – сервису нужны только токен и, при выбранной настройке, IP;
- показывать всем пользователям видимую головоломку;
- логировать полное тело анкеты в Nginx или application logs.
