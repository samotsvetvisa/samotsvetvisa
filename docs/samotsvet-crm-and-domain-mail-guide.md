## 1. Что меняется в обработке заявок

Новая анкета состоит из двух экранов, но до установки расширения создает только одну запись.

1. Короткий этап занимает около 2–3 минут. Результат рассчитывается локально в браузере и еще не передается в CRM. Пользователь видит:
   - направления, которые стоит проверить;
   - ориентировочную готовность профиля;
   - объяснение следующего шага.
2. Затем пользователь выбирает один из двух вариантов: отправить короткую анкету или сначала дополнить ее гражданством, статусом, целью, опытом, доказательствами, ссылками, семейной ситуацией и историей подач.
3. В обоих случаях сайт выполняет один POST в действующий Lead Capture и создает ровно один Lead. Результат и внутренний приоритет записываются текстом в уже существующие поля; новые поля CRM для работы сайта не обязательны.
4. На сайте не показывается процент одобрения. Автоматический результат — это первичный скрининг, а не юридическое заключение.
5. Внутренний Tier нужен только для очереди ответов и не означает вероятность получения визы.

Каждой попытке присваивается стабильный идентификатор вида `SV-...`. В текущем режиме он помогает найти обращение. После установки расширения этот же идентификатор позволит при необходимости включить раннюю запись короткого этапа и безопасно присоединять последующее дополнение без дублей.

## 2. Целевые поля Lead в EspoCRM

Поля ниже не нужны для запуска текущей одноразовой отправки. Они улучшают фильтрацию, отчеты и автоматическое слияние, поэтому добавляются только после резервной копии и теста расширения.

### Поля анкеты

| Поле EspoCRM | Тип | Назначение |
| --- | --- | --- |
| `cAssessmentId` | Varchar | Общий ID двух этапов |
| `cAssessmentStage` | Enum | `Short` или `Detailed` |
| `cAssessmentResult` | Text | Результат, показанный пользователю |
| `cRouteCandidates` | Text | Маршруты для содержательной проверки |
| `cFitScore` | Int 0–3 | Базовое совпадение цели и типа профиля с направлением |
| `cEvidenceScore` | Int 0–3 | Текущий уровень внешних и независимых доказательств |
| `cUrgencyScore` | Int 0–3 | Насколько быстро человеку нужен следующий шаг |
| `cReadinessScore` | Int 0–3 | Насколько профиль готов к документальной проверке |
| `cTotalScore` | Int 0–12 | Сумма четырех внутренних оценок |
| `cTier` | Enum | `A`, `B` или `C` |
| `cNextStep` | Text | Рекомендуемое действие |
| `cFollowUpAt` | DateTime | Срок первого ответа |
| `cFollowUpTaskCreated` | Boolean | Контроль создания задачи |

Существующие поля формы сохраняются: контакт, страна, маршрут, цель, сроки, гражданство, место проживания, семья, занятость, профиль, ссылка, доказательства, текущий этап, история подач, источник, UTM, landing page, referrer, время и версия согласия.

### Значение Tier

| Tier | Балл | Как использовать |
| --- | ---: | --- |
| A | 9–12 | Быстрое предметное обращение: проверить в первую очередь |
| B | 6–8 | Нужен обычный разбор и уточняющие вопросы |
| C | 0–5 | Ранняя стадия, долгий горизонт или пока слабое совпадение; не отказывать автоматически |

Tier не следует показывать клиенту и нельзя описывать как «шанс на одобрение». Обращение с Tier C может быть хорошим кандидатом на программу развития профиля.

## 3. Воронка Lead

Рекомендуемые статусы:

1. `New` — анкета получена, ответа еще не было.
2. `Screening` — специалист разбирает факты и возможные маршруты.
3. `Qualified` — есть предметный следующий шаг.
4. `Consultation` — назначен звонок или письменный разбор.
5. `Proposal` — направлены объем, сроки и стоимость.
6. `Nurture` — профиль нужно развивать; зафиксирована дата возвращения.
7. `Converted` — создан Contact и, при необходимости, Opportunity.
8. `Lost` — работа не началась; причина обязательна.

Не используйте статус `Lost` для человека без публикаций. Если маршрут в принципе доступен, но профиль не готов, это `Nurture` с планом на 3–12 месяцев.

### Причины Lost

- нет рабочего маршрута по исходным фактам;
- не совпали сроки;
- не совпал бюджет;
- клиент выбрал другого исполнителя;
- нет ответа после согласованного числа касаний;
- дубль или спам;
- другая причина с комментарием.

## 4. Карточка и список

### Карточка Lead

Разделите Detail layout на пять панелей:

1. **Контакт:** имя, контакт, страна проживания, гражданство, семья.
2. **Предварительная оценка:** Assessment ID, этап, Tier, четыре компонента балла, результат, маршруты для проверки.
3. **Профиль:** занятость, описание, ссылка на CV/LinkedIn, доказательства, история подач.
4. **Работа с лидом:** статус, ответственный, следующий шаг, ответить до, задачи и коммуникация.
5. **Источник и согласие:** form source, UTM, landing page, referrer, consent timestamp, privacy version.

### Колонки списка

`Created At` → `Name` → `Contact` → `Country` → `Routes` → `Tier` → `Status` → `Reply by` → `Assigned User`.

### Сохраненные фильтры

- **Просрочен ответ:** `cFollowUpAt < now`, статус не `Converted` и не `Lost`.
- **Tier A:** `cTier = A`.
- **Не дополнили анкету:** `cAssessmentStage = Short` — только после включения раннего сохранения первого этапа.
- **Развитие профиля:** `status = Nurture`.
- **По источнику:** UTM source/campaign или form source.

На Dashboard достаточно четырех List dashlets: «Новые сегодня», «Просрочен ответ», «Tier A», «Nurture на этой неделе».

## 5. Устанавливаемое расширение

Исходники находятся в `ops/espocrm-samotsvet`. Архив собирается как `ops/dist/samotsvet-assessment-pipeline-1.0.0.zip`.

Расширение:

- добавляет поля оценки и индексы;
- считает общий балл и Tier на сервере;
- находит короткий этап по `Assessment ID` и присоединяет подробные поля;
- удаляет техническую карточку-дополнение после слияния;
- устанавливает срок ответа на следующий рабочий день;
- создает связанную Task для ответственного пользователя.

Сайт уже работает без расширения в режиме «одна анкета — один Lead». Не переключайте его на раннюю запись первого этапа до завершения теста из раздела 6.

### Установка

Перед установкой сделайте резервную копию базы и каталога CRM.

1. В EspoCRM откройте `Administration → Extensions`.
2. Загрузите ZIP и нажмите `Install`.
3. Откройте `Administration → Rebuild` и выполните rebuild.
4. Проверьте поля в `Administration → Entity Manager → Lead → Fields`.
5. Настройте Detail и List layouts по разделу 4.
6. Включите Kanban view для Lead.
7. В действующей записи `Administration → Lead Capture` добавьте в `Payload Fields`:
   - `cAssessmentId`;
   - `cAssessmentStage`;
   - `cAssessmentResult`;
   - `cRouteCandidates`;
   - `cFitScore`;
   - `cEvidenceScore`;
   - `cUrgencyScore`;
   - `cReadinessScore`;
   - `cNextStep`;
   - все существующие поля анкеты и атрибуции.
8. Назначьте Target Team и ответственного пользователя.
9. Не включайте double opt-in: это не рекламная подписка.

После этих действий код сайта можно отдельно переключить на раннее сохранение короткого этапа. До этого новые поля не отправляются публичной формой.

### Ограничение CORS

Сейчас EspoCRM по умолчанию может отвечать любому Origin. На сервере в `data/config.php` задайте только домены сайта:

```php
'leadCaptureAllowOrigin' => 'https://samotsvetvisa.com',
```

Если используется `www`, лучше перенаправлять его на основной домен. Не оставляйте `*`.

### Rate limit на Nginx

Honeypot остается на сайте. На сервере добавьте ограничение частоты для публичного LeadCapture endpoint. Начальная настройка: не более пяти POST-запросов в минуту с одного IP, короткий burst до трех запросов. Не подключайте reCAPTCHA без отдельной оценки обработки данных: встроенная форма EspoCRM использует Google reCAPTCHA v3.

## 6. Проверка CRM после установки

Тестировать нужно в таком порядке:

1. Временно включить раннее сохранение на тестовой копии формы и отправить один короткий тест с адресом, который явно помечен как тестовый.
2. Проверить одну карточку Lead, Assessment ID, Tier, срок ответа и Task.
3. Дополнить тот же профиль на втором этапе.
4. Убедиться, что активная карточка осталась одна и получила значение `Detailed`.
5. Проверить, что реальный текст, ссылки и UTM не потерялись.
6. Проверить отказ CORS для постороннего Origin.
7. Проверить honeypot и rate limit.
8. Удалить тестовую карточку и связанную Task.

До прохождения этого теста сохраняйте текущий режим одного POST: он уже дает пользователю два уровня анкеты, но исключает дубли без зависимости от расширения.

## 7. Безопасность и обслуживание CRM

Минимальный регламент:

- доступ администратора только тем, кому он действительно нужен;

## 8. Почта на домене: рекомендуемый бесплатный вариант

Для первого запуска подходит VK WorkSpace на тарифе «С рекламой». Это полноценная входящая и исходящая почта на собственном домене, а не простая переадресация.

У бесплатного тарифа есть существенные ограничения:

- не более пяти пользователей;
- реклама в интерфейсе;
- автоматическая подпись VK WorkSpace во всех исходящих письмах;
- нельзя подключить обычный внешний почтовый клиент;
- до трех активных сессий на один аккаунт;
- 3 ГБ на весь домен;
- при отсутствии активности администраторов и пользователей в течение шести месяцев аккаунт может быть удален без восстановления.

Условия нужно повторно проверить перед подключением: [тариф «С рекламой»](https://workspace.vk.ru/docs/saas/tariffs/manage-free-tariff), [общая инструкция подключения](https://workspace.vk.ru/docs/saas/get-started).

Для Samotsvet достаточно начать с одного реального пользователя `hello@samotsvetvisa.com` и двух групповых адресов:

- `privacy@samotsvetvisa.com` — запросы по персональным данным;
- `team@samotsvetvisa.com` — общий адрес, если он действительно нужен.

Группы направляют письма существующим пользователям и не занимают отдельное рабочее место. Не создавайте пять отдельных ящиков без необходимости.

## 9. Пошаговая настройка VK WorkSpace

### Шаг 1. Подготовка

До изменения DNS:

1. Убедитесь, что есть доступ к DNS-зоне `samotsvetvisa.com`.
2. Сохраните снимок текущих DNS-записей.
3. Не меняйте A, AAAA, CNAME и GitHub Pages записи сайта.
4. Уменьшать TTL заранее необязательно, но значение 300–600 секунд ускорит переключение.

Почтовые записи MX и TXT не меняют хостинг сайта.

### Шаг 2. Создание организации

1. Откройте [VK WorkSpace](https://workspace.vk.ru/) и создайте организацию.
2. Выберите подключение существующего домена.
3. Укажите `samotsvetvisa.com` без `https://` и без `www`.
4. Используйте личный резервный адрес владельца только для восстановления доступа.
5. Включите двухфакторную аутентификацию владельца.

### Шаг 3. Подтверждение домена

Выберите подтверждение через DNS TXT. VK покажет уникальное имя и значение записи.

1. В панели DNS создайте TXT ровно с тем Host/Name и Value, которые показаны в VK.
2. Не добавляйте кавычки вручную, если панель делает это сама.
3. Дождитесь распространения DNS и нажмите проверку в VK.

Не используйте подтверждение HTML-файлом: сайт статический и DNS-подтверждение проще сохранить при следующих релизах.

### Шаг 4. MX

Удалите старые MX только после сохранения их значений. Добавьте MX, который показывает VK WorkSpace. Типичное значение сервиса — `emx.mail.ru` с приоритетом 10, но в DNS нужно копировать актуальное значение из панели VK, а не полагаться на пример.

У домена не должно оставаться конфликтующих MX другого провайдера.

### Шаг 5. SPF

Добавьте TXT для корня домена со значением, показанным VK. В DNS должна быть только одна SPF-запись, начинающаяся с `v=spf1`.

Если SPF уже есть, нельзя создавать вторую запись. Нужно объединить разрешенные отправители в одну строку. После запуска CRM SMTP строка должна учитывать и почтового провайдера, и сервер, который действительно отправляет системные письма.

### Шаг 6. DKIM

1. В панели VK откройте DKIM.
2. Создайте TXT с selector/Host и длинным публичным ключом, которые покажет сервис.
3. Скопируйте значение одной строкой; DNS-панель при необходимости разделит длинный TXT сама.
4. Дождитесь статуса успешной проверки.

Приватный ключ остается у почтового провайдера и в DNS не публикуется.

### Шаг 7. DMARC

После работающих SPF и DKIM создайте адрес или группу `dmarc@samotsvetvisa.com`, затем TXT:

```text
Host: _dmarc
Value: v=DMARC1; p=none; rua=mailto:dmarc@samotsvetvisa.com; adkim=s; aspf=s; pct=100
```

Режим `p=none` только собирает отчеты. Через 2–4 недели, если легитимная отправка проходит SPF/DKIM alignment, можно перейти к `p=quarantine`, а затем к `p=reject`. Не начинайте с `reject`: можно заблокировать собственные письма CRM.

### Шаг 8. Адреса

1. Создайте пользователя `hello`.
2. В `Почта → Группы рассылок` создайте `privacy` и добавьте владельца `hello`.
3. При необходимости создайте `team` тем же способом.
4. Включите восстановление доступа и сохраните резервные коды 2FA вне CRM.

### Шаг 9. Проверка

Проверьте четыре сценария:

1. письмо с внешнего адреса на `hello@`;
2. ответ с `hello@` на внешний адрес;
3. письмо на `privacy@` и получение его владельцем;
4. заголовки принятого письма: `SPF=pass`, `DKIM=pass`, `DMARC=pass`.

Только после успешной проверки замените Gmail на `hello@samotsvetvisa.com` в контактах, футере, schema.org, политике, согласии и CRM.

## 10. Почта и EspoCRM

Бесплатный тариф VK ограничивает подключение внешних почтовых клиентов. Поэтому нельзя заранее считать, что его SMTP подойдет для EspoCRM.

Практичная последовательность:

1. Запустить `hello@` для ручной переписки через веб-интерфейс VK.
2. Проверить в выбранном тарифе наличие SMTP и пароля приложения.
3. Если SMTP недоступен, выбрать одно из двух решений:
   - платный тариф VK WorkSpace с SMTP/почтовыми клиентами;
   - отдельный исходящий SMTP на российской инфраструктуре с корректными SPF, DKIM, DMARC, PTR и журналами.
4. Только после этого подключить System Email и Group Email Account в EspoCRM.

Самостоятельный почтовый сервер формально может быть бесплатным по лицензии, но не является бесплатным в эксплуатации: нужны PTR/rDNS, репутация IP, защита от спама, обновления, резервные копии и постоянный мониторинг. На одном сервере с CRM его лучше не размещать.

## 11. Почему не Cloudflare Email Routing

Cloudflare Email Routing бесплатен и удобен для входящей переадресации, но это не полноценный почтовый ящик: ответ обычно уходит с конечного адреса, а не с адреса домена. Если конечный адрес — Gmail, переписка продолжает обрабатываться иностранным сервисом. Для публичного адреса и требования убрать Gmail это слабее, чем VK WorkSpace.

Официальное описание: [Cloudflare Email Routing](https://developers.cloudflare.com/email-routing/).

## 12. Аналитика без лишней передачи данных

Сейчас на сайте нет сторонней аналитики, рекламных пикселей и cookie. Это соответствует опубликованной политике. Анкета уже создает локальные события `samotsvet:assessment`, но они никуда не отправляются:

- `short_result` — пользователь получил предварительный результат;
- `detail_open` — открыл подробный этап;
- `basic_success` — отправил короткий профиль;
- `detail_success` — отправил подробный профиль;
- события с суффиксом `_error` — ошибка отправки.

Следующий безопасный вариант — self-hosted Umami или Matomo на российской инфраструктуре с отключенными профилями посетителей, записью полного URL и длительным хранением IP. После установки нужно:

1. передавать только имя события, язык, тип страницы и выбранное направление;
2. не передавать имя, контакт, текст анкеты, Assessment ID, referrer с query-параметрами и содержимое полей;
3. обновить политику до включения аналитики;
4. проверить необходимость cookie-баннера по фактической конфигурации;
5. добавить в CRM ежемесячный отчет: `short_result → detail_open → отправка → Qualified → Proposal → Converted`.

Код событий уже подготовлен. Сетевую аналитику намеренно не включаем, пока не выбран и не настроен российский сервер аналитики.

## 13. Что потребуется от владельца

Большую часть настройки сайта и CRM можно подготовить заранее. Для боевого завершения нужны действия, которые нельзя безопасно сделать без доступа владельца:

- вход администратора в EspoCRM;
- загрузка и подтверждение установки расширения;
- доступ к DNS-зоне домена;
- регистрация владельца организации VK WorkSpace и подтверждение телефона;
- один тестовый лид после установки;
- финальное решение, допустима ли подпись VK в бесплатном тарифе.

Пароли и резервные коды не следует передавать в переписке. Используйте защищенную форму входа, когда система ее запросит.
